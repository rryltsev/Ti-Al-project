# Возобновление обучения GRACE с состоянием Adam

Для 14 финальных состояний Adam можно восстановить по два исходных файла TensorFlow, `checkpoint.index` и `checkpoint.data-00000-of-00001`. В них сохраняются веса, счётчик и слоты оптимизатора. Источники и SHA-256 обоих файлов, соответствующего финального чекпойнта и пакета для восстановления перечислены для каждого расчёта в [индексе Adam](grace-optimizers.csv).

| Выборка | Модели | Seed | Число состояний | Размер пакетов |
| --- | --- | --- | ---: | ---: |
| PBE N694 | full, restricted_radial | 10, 20, 30 | 6 | 71 623 167 байт |
| PBE N200 | full, restricted, restricted_mlp, restricted_radial | 20, 30 | 8 | 78 287 126 байт |

В каждом исходном data shard 174 120 269 байт совпадают с тензорами соответствующего финального чекпойнта GRACE. Репозиторий хранит сжатые остальные байты, исходный индекс TensorFlow и таблицу позиций тензоров. Восстановление проверяет контрольные суммы сжатого пакета, исходных весов и обоих выходных файлов. Общий объём восстановленных файлов составляет 7 222 018 791 байт. [Пакеты](../research/grace-final/optimizers/) · [Восстановление финальных моделей и базы](grace-final-models.md)

## Один расчёт с нового компьютера

Из корня клона сначала восстановите финальные веса нужного расчёта. Если базовая модель уже загружена, можно использовать параметр `--base` с локальным путём по инструкции выше. Вторая команда использует те же веса и файлы из Git. Для обеих достаточно стандартной библиотеки Python 3.10+.

```sh
python tools/restore_grace_models.py --case PBE-full-N694-seed10 --download-base
python tools/restore_grace_optimizers.py --case PBE-full-N694-seed10
```

Выходные файлы находятся в `tmp/grace-optimizers/PBE-full-N694-seed10/`. В среде обучения путь к префиксу TensorFlow заканчивается на `/checkpoint`. Схема модели, маска обучаемых параметров и версия программного окружения должны соответствовать выбранному случаю. Эта проверка подтверждает восстановление файлов. Новый шаг оптимизации в рамках резервного копирования не выполнялся.

Для произвольного расположения весов используйте `--models`, для каталога результата — `--output`. Ключ `--list` выводит 14 доступных имён. Флаг `--all` восстанавливает все состояния при наличии соответствующих 14 наборов финальных весов.

## Первичные архивы

Для шести N694 исходные `optimizer-final.tar.gz` входят в локальный файл `audit/storage-20261114/offloaded-vasp-restarts-and-grace-optimizers.tar.gz`. Для восьми N200 каждый такой TAR вложен в именованный архив `research/tial_fm/runs/grace-pbe-n694-20261110-01/storage-recovery/grace-pbe-seeds-20261110-01__<case>.tar.gz`. Все 14 восстановленных пар `index/data` сверяются с независимым чтением соответствующего исходного архива. Поле `original_archive_sha256` относится к внутреннему `optimizer-final.tar.gz`, поле `sha256` — к несжатому data shard. [Манифест переноса N694](../audit/storage-20261114/offload-manifest.json) · [План переноса N200](../research/tial_fm/runs/grace-pbe-n694-20261110-01/storage-recovery/plan.json)

Если нужны промежуточные чекпойнты, старые варианты best/last или точные исходные архивы для аудита, воспользуйтесь [реестром 40 архивов хранения](research-recovery.csv). Их совокупный размер составляет 6 218 149 936 байт. Каждая строка задаёт имя TAR, путь относительно исходной рабочей папки TiAl, размер и SHA-256. На исходной рабочей станции это три каталога `research/tial_fm/runs/<серия>/storage-recovery/` для `grace-n200-mask-ablation-20261109-01`, `grace-pbe-seeds-20261110-01` и `grace-pbe-n694-20261110-01`. Ориентируйтесь на фактический статус публикации в каталоге релиза. Если байты конкретного исторического TAR там отсутствуют, скопируйте его с исходной рабочей станции или её резервной копии и сверьте SHA-256. При первоначальном освобождении квоты на UMT часть исходных файлов была удалена после подтверждённого переноса. [Отчёт о переносе](../research/tial_fm/reports/24_grace_quota_recovery.md)
