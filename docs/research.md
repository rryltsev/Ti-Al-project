### Числа для сверки редакции статьи

В архивной проверке на 49 общих структурах RMSE энергии составила 1,47 / 1,77 / 1,58 мэВ/атом для PBE / PBEsol / r²SCAN. Это результат на конкретном наборе и конкретных весах. PBE 20k был выбран после просмотра Test50. Исторические диагностические таблицы в SI относятся также к другим чекпойнтам и выборкам. [Метрики Test49](../manuscript/supporting_data/test49_metrics.json) · [реестр весов и история выбора](../research/tial_fm/manifests/models.json).

Для чистого Ti оценки температуры плавления составили около 1760 / 1750 / 1855 K при экспериментальных 1943 K. У PBE наблюдались кристаллизация при 1750 K и плавление при 1775 K. Для жидкости при 1873 K средние абсолютные отклонения плотности составили 0,112 / 0,246 / 0,189 г/см³. В серии энтальпии смешения при 2000 K продлённые до 60 пс траектории r²SCAN дали наименьшее среднее расхождение с использованной калориметрией, около 1,5 кДж/моль. Минимум около доли Al 0,5–0,6 оказался слишком глубоким. [Выводы и ограничения](../manuscript/sections/conclusions.tex) · [первичные таблицы рисунков](../deliverables/2026-11-03/figure_data).

Для вязкости при 1873 K таблицы от 6 ноября отдельно дают прогнозы при подстановке экспериментальной, PBE- и r²SCAN-энтальпии. В сравнении KRP, Moelwyn-Hughes, Schick и Kaptay на пяти составах Takeda наименьшие ошибки дала модель Schick. Для воспроизведения сравнения используйте значения при экспериментальных составах, кривые по составу и CSV с метриками. [Протокол и уравнения](../deliverables/2026-11-06/Fig07_viscosity_models/README_RU.txt) · [метрики](../deliverables/2026-11-06/Fig07_viscosity_models/model_metrics_vs_Takeda.csv).

## Как продолжить эксперимент N200/N694

1. Откройте [протокол](../research/tial_fm/protocol/benchmark_protocol.md), [активный манифест](../research/tial_fm/manifests/active_dataset.json) и [отчёт по группировке](../research/tial_fm/reports/07_grouped_split.md). Общее множество содержит 992 геометрии с метками трёх функционалов. Разбиение 694/149/149 закреплено по группам. N200 вложен в обучающие 694. Исходные идентификаторы всех жидкостных траекторий восстановлены лишь частично. Архивные 49 структур, validation149 и test149 имеют разное назначение.
2. Пакеты DeepMD в клоне содержат координаты, ячейки, типы, энергии, силы и вириалы с исходной структурой каталогов. Команды ниже восстанавливают их в `research/tial_fm/datasets`. SHA-256 и число файлов каждого архива записаны в [индексе](research-data-archives.csv). Для чтения отчётов и CSV распаковка не нужна. Для отдельного запуска выберите его имя из списка и передайте как префикс в `--data`, чтобы восстановить предсказания, силы и численные входы. Требуется Python 3.9 или новее.

   ```sh
   python tools/restore_research.py --list
   python tools/restore_research.py --data common992-grouped-v1-20261106-02
   python tools/restore_research.py --data nested-train-v1-20261106
   python tools/restore_research.py --data grace-pbe-n694-20261110-01
   ```

3. Сопоставьте [исходные конфигурации](../research/tial_fm/configs) с `runs/<run>/package/plan.json`, входом конкретного случая и результатами в `collected` или `collected-final`. [Код подготовки, проверок и агрегации](../research/tial_fm/scripts) сопровождается фактическими Slurm-скриптами в каталогах пакетов. Записанные абсолютные пути Windows, имена окружений и пути `/home6/u3129` относятся к исходным машинам. Например, `audit_initial.py` использует путь к архиву Desktop, а `cluster_pilot.py` использует OpenSSH и исторический псевдоним `mlip-umt`. Если соседнего MLIP-research нет, встроенный `scripts/cluster_ssh.py` читает параметры стандартного OpenSSH-профиля. На другом компьютере укажите фактическое расположение исходников, настройте псевдоним для нужного аккаунта, локальный ключ и доверенный ключ хоста. Для нового расчёта выбирайте UMT-аккаунт вместе с пользователем и используйте новый идентификатор запуска.
4. Для повторного DPA4-инференса возьмите один из [24 финальных чекпойнтов с SHA-256](research-dpa4-checkpoints.csv). 12 PBE-весов совпадают с SHA-256 из [протокола Ti₃Al](../research/tial_fm/runs/ti3al-pbe-phonons-20261109-02/package/models.json). Эти объединённые веса пригодны для экспорта. Для продолжения оптимизатора требуются также нативные состояния обучения. Для нового многократного инференса экспортируйте выбранный вес с `DP_TRITON_INFER=2` при freeze, проверьте E/F/stress на идентичных структурах и загружайте проверенный `.pt2`. Исторические результаты получены теми версиями, которые указаны в соответствующем отчёте.
5. Чтобы получить финальные модели GRACE, используйте [руководство по восстановлению](grace-final-models.md). В Git сохранены графы, метаданные и обратимые отличия для 22 случаев, а SHA-256 зафиксированной базовой модели указан в манифесте. Один вызов `python tools/restore_grace_models.py --all --output tmp/grace-models` собирает исходное дерево UMT относительно `tial-fm-research/`. Нативные файлы финального checkpoint находятся в `<run>/cases/<case>/final-checkpoint/`, экспорт — в `seed/<seed>/final_model/`, архитектура — в `seed/<seed>/model.yaml`. В [индексе моделей](grace-final-models.csv) приведены размер и SHA-256 каждого из 198 восстановленных файлов.
6. Финальное состояние Adam для 14 серий восстанавливается по [отдельной инструкции](grace-optimizers.md). Для промежуточных весов и первичных архивов используйте [индекс имён, исходных путей и SHA-256](research-recovery.csv). В UMT-каталоге соответствующего исходного запуска хранится журнал прежнего размещения. Для GRACE-серий, где применялось архивирование финального состояния, исходный путь имеет вид `<run>/cases/<case>/seed/<seed>/checkpoints/optimizer-final.tar.gz`. Исходный корень UMT — `/home6/u3129/tial-fm-research/`. В [отчёте о квоте](../research/tial_fm/reports/24_grace_quota_recovery.md) указано, какие промежуточные файлы переносили на рабочую станцию и как проверяли их хеши.

## Продолжить обучение с финального шага

Для 24 случаев DPA4 скопированы с UMT и сверены по исходным журналам файлы `checkpoints/model.ckpt-10000.pt` (N200) или `checkpoints/model.ckpt-34700.pt` (N694). Они содержат состояние обучения и оптимизатора. Таблица указывает шаг, функционал и маску в имени случая, точный путь внутри ZIP, путь на UMT, размер и SHA-256. [Чекпойнты для рестарта DPA4](dpa4-training-restarts.csv).

```sh
python tools/release_assets.py --list --group dpa4-restart
python tools/release_assets.py --get --name "dpa4-final-training-PBE-N694.zip"
python -m zipfile -e downloads/dpa4-final-training-PBE-N694.zip .
```

Выберите конфигурацию и протокол соответствующего запуска. Для продолжения обучения используйте checkpoint из подкаталога `checkpoints`; соседний `merged` содержит объединённые веса для экспорта. Для GRACE аналогичные команды, версии TensorFlow и контрольные суммы сохранены в [руководстве по Adam](grace-optimizers.md).
