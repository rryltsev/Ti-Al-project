# Влияние отдельных ECI на границы при 1000 K

Здесь метка paper относится к исходной реконструкции S1 и рис. 2. Точные электронные ECI C46 доступны в [сопоставлении авторских данных](../../author_comparison/README.md).

Для десяти контролируемых гамильтонианов выбраны пять подстановок в статике и те же пять в гармоническом приближении. Направление `paper_to_masked` означает, что указанные коэффициенты из независимой подгонки ATAT/MTP пересажены в реконструкцию статьи. В `masked_to_paper` исходной служит независимая подгонка. В HA заменяется эффективный коэффициент с обеими составляющими, J_static + J_vib(1000 K).

| Фон | Замена | Что измеряет сравнение |
|---|---|---|
| Статья | t334 | Сдвиг от одной тройки t334 |
| Статья | t123 | Сдвиг от одной тройки t123 |
| Статья | t334 и t123 | Совместный сдвиг двух троек на исходном фоне |
| Собственная подгонка | t334 и t123 | Эффект возврата обеих троек на другом фоне |
| Статья | p1…p7 | Совместный сдвиг от семи пар |

Четыре крайних гамильтониана взяты из архивов выполненных окон. Статика статьи использует таблицу S1, HA статьи использует реконструкцию фононного вклада по рисунку 2. В обоих наших гамильтонианах используется одна и та же маска динамически устойчивых обучающих структур при опорном объёме. Для каждой модели сверены SHA-256 старого файла ECI и таблицы окон. Исходные записи перечислены в [baselines.json](baselines.json). Численные коэффициенты, замены и обменные потенциалы зафиксированы в [hybrids/metadata.json](hybrids/metadata.json).

В каждом сценарии 35 центров c₀ = 0.02, 0.03, …, 0.36, размер HCP-ячейки 16×16×10×2 = 5120 узлов и безразмерная жёсткость κ = 100. На один узел приходится одна попытка выбора за проход в среднем. После 10 000 проходов уравновешивания следуют 40 000 производственных, записывается каждый десятый. В пределах каждого сравнения фиксирован обменный потенциал исходного фона. Формула для извлечения химпотенциала использует фактический состав окна. Базовым сценариям и десяти подстановкам назначены разные seed.

## Какие данные позволяют проверить замену

На каждом кадре полная энергия вычисляется по формуле H = NJ₀/2 + (2n_Al − N)J₁ + Σₐ SₐJₐ. Величина Sₐ означает целую сумму произведений спинов по всем кластерам орбиты с учётом повторяемости. В прежних MC-архивах записаны число Al, параметр дальнего порядка, объём и суммарная энергия текущей модели. Для новой выборочной замены нужно знать Σₐ SₐΔJₐ. Скаляр дальнего порядка задаёт заселённость подрешёток, но не определяет соседство атомов. Поэтому из старого CSV нельзя вычислить вес такой замены. Изменения константы и точки вычисляются по n_Al, а масштабирование всех неаффинных взаимодействий вычисляется из прежней суммарной энергии. При фиксированном объёме аффинная по составу добавка оставляет концентрации контактов общей касательной неизменными.

Опция `orbit-sums` в [vcs.cpp](../../mc/vcs.cpp) добавляет 18 целых орбитных сумм в каждый новый кадр. На сохранённой микроконфигурации энергию произвольной подстановки можно восстановить и проверить с точностью записи. Чтобы оценить новое равновесное распределение посредством перевзвешивания, отдельно проверяют перекрытие энергий и эффективное число статистически независимых кадров. Прямой MC для десяти заданных подстановок обеспечивает независимое измерение положения контактов.

## Воспроизведение локально

Из корня рабочего проекта следующий вызов воссоздаёт все десять строк коэффициентов и 350 окон в новом каталоге.

```bash
python phase_reproduction/eci_boundary/mc/prepare.py --plan phase_reproduction/eci_boundary/mc/hybrids_1000K.json --output new_hybrid_inputs
```

Проверка на 5120 узлах и одинаковом seed дала совпадение всех 100 исходных кадров при включённой и выключенной записи орбит. При независимом пересчёте по CSV наибольшее отклонение от записанной энергии составило 5.0 × 10⁻¹² эВ/атом. Тот же код прошёл проверку средних состава и объёма по точному распределению конечной модельной решётки.

```bash
python phase_reproduction/eci_boundary/mc/verify_orbits.py path/to/samples.csv.gz --output orbit_check.json
```

Менеджер `phase_reproduction/mc/umt_run.py` принимает серию `hybrids_1000K`, действия `stage`, `submit`, `status`, `fetch` и явный аргумент `--account`. При необходимости проект Slurm указывается отдельно через `--allocation`. Для завершённого сценария `fetch --slice ИМЯ 1000` загружает его 35 окон с проверкой SHA-256 и последовательности кадров.
