# Расчёт Ti–Al на CPU UMT

Задания используют учётную запись `u3129` и Slurm-проект `imet-2026-2`. Выделяются CPU и память. Для коротких расчётов подходят разделы `apollo,nompi,debug`. Все новые файлы на UMT размещаются в `/home6/u3129/tial-pd-20261124-atomistic/<имя-серии>`. Параметры соединения берутся из локального проекта `MLIP-research`.

Программа `umt_job.py` создаёт отдельный каталог на каждую попытку, записывает хеши входных файлов, запоминает номер Slurm и сверяет хеши полученных результатов. Файлы задания имеют разные базовые имена, исполняемый сценарий называется `job.sh`. Пример повторного получения расчёта:

```powershell
python phase_reproduction/cluster/umt_job.py status ha-pilot-01
python phase_reproduction/cluster/umt_job.py fetch ha-pilot-01 results.tar.gz inputs.sha256
```

## Расчёт нового ATAT-набора

Для полного цикла `volume_series.py` принимает замороженный набор с `design.csv`, `jobs.csv` и файлами `cells/*.cfg`. Входные хеши связывают декорации с каждой статической и фононной меткой. Одна задача Slurm вычисляет 46 структур при одном объёме, используя одиночные одноядерные процессы для независимых структур. В `outcomes.json` фиксируются результат и продолжительность каждой точки. При ошибке следует просмотреть индивидуальный лог и сохранить успешно завершённые точки.

```powershell
python phase_reproduction/cluster/volume_series.py submit --design <каталог-ATAT-набора>
python phase_reproduction/cluster/volume_series.py status
python phase_reproduction/cluster/volume_series.py fetch-labels
python phase_reproduction/cluster/volume_series.py fetch-raw
python phase_reproduction/cluster/verify_raw.py
```

На UMT каждая завершённая серия объёма сохраняет `results.tar.gz` со всеми численными артефактами и `labels.tar.gz` с компактными данными для подгонки. Серия при опорном объёме использует восемь CPU, остальные — по три. После завершения `fetch-labels` сохраняет локальные копии компактных меток каждого объёма, журналов Slurm и контрольных сумм входных файлов.
